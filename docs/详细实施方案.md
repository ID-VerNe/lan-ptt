## 0. 三件必须先说清的事

1. **本项目请挂 `GPL-3.0-or-later`，不要挂 GPL-2.0-only。** sunsetripple 与 google/oboe 是 **Apache-2.0**，Apache-2.0 的专利终止条款与 GPLv2 不兼容、与 **GPLv3 兼容**。挂 GPLv2 就不能合法 copy sunsetripple 的代码，整个方案前提不成立。
2. **"开源"不等于"任意代码都能 copy"。** GPL 身份解除了 GPL/AGPL 的传染顾虑，但**无 LICENSE 文件的仓库仍是"保留所有权利"**。最关键的 `zthenea/MotoIntercom`（唯一实现 `startLocalOnlyHotspot` 的项目）无 LICENSE，仍只能 clean-room 重写或参考思路。
3. **sunsetripple 是 Flutter 多端工程**（Dart 业务层 + Android Kotlin 原生层 + iOS/HarmonyOS + BLE + 聊天 + 更新 + 加密）。要"copy 大部分代码"就必须接受保留 Flutter/Dart 技术栈；若改成纯 Kotlin 原生，`lib/core/session/` 与 `lib/core/transport/` 的会话状态机与传输层需要整层重写。本方案**默认保留 Flutter 层**，这符合"不 fork、按模块重组"的 compose 口径：不 `git clone` 后改，而是把对讲主干摘进新工程，删掉约一半无关代码并替换音频引擎。

### 一个有利发现

README:47/72 明确：**Wi-Fi 房已支持"手机热点"**（同一局域网 / 手机热点 / Wi-Fi Direct 三种），且 `lan_discovery.dart:181-196` 同时广播 `255.255.255.255` 与 `/24` 定向地址（如 `192.168.43.255`）。因此**"一台手机开系统热点、其余连上"这条路径不用写任何建网代码**，UDP 发现直接能跑。只有"App 内一键开热点"才需要 `startLocalOnlyHotspot`，列为 P2 可选项。

## 3. 总体架构

```
┌─ Flutter / Dart 层（copy 主干，裁剪无关模块）─────────────────────┐
│  RoomSession  房间状态机 / PTT / 成员 / 房主 failover              │
│  LanTransport TCP 8988 控制 + UDP 8989 音频 + 房主 _relayAudio     │
│  LanRoomDiscovery UDP 8990 广播（255.255.255.255 + /24 定向）      │
│  Frame 6B 头 + FrameType（精简后 8 类）                           │
└───────────────────────┬──────────────────────────────────────────┘
                        │ MethodChannel / EventChannel
┌───────────────────────▼──────────────────────────────────────────┐
│ Android 原生层（P0 copy，P1 换引擎）                                │
│  PlatformAudioPlugin  采集/播放/3A/编解码编排                       │
│  OpusCodec            P0: Concentus 16kHz/20ms；P1: libopus 48k/10ms│
│  JitterBuffer         固定 3 帧 → 自适应 20~60ms                    │
│  IntercomForegroundService（最小 FGS，非锁屏）                      │
│  native/ CMake        audio_dsp 混音 + ring_buffer + protocol_frame  │
└───────────────────────┬──────────────────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────────────────┐
│ 系统：手机热点（用户手动开，P2 可加一键开热点）                     │
│ AAudio/Oboe（P1）· AudioRecord/AudioTrack（P0）· 硬件 AEC/NS/AGC    │
└──────────────────────────────────────────────────────────────────┘
```

**拓扑**：星形。客户端只发房主，房主 `_relayAudio()` 转发其他成员（`lan_transport.dart:649,663,704`）——这正是合并方案裁决的"房主转发"，sunsetripple 已实现，无需自研。房间规模控制在 6 人以内（沿用上游项目描述的上限，并在代码里加显式校验）。

## 6. 关键改造点（代码级）

### 6.1 延时：先调参，再换引擎（120ms 目标）

现状瓶颈（`PlatformAudioPlugin.kt:267-276 / 466-475`、`JitterBuffer.kt:25-27`）：

| 环节 | 现状 | 调参后（P0） | P1（Oboe+libopus） |
|---|---|---|---|
| 采集 | 20ms 阻塞读满 320 样本 + buffer `max(min,640*4)`=80ms | 帧仍 20ms，buffer 降到 `*2`=40ms | 10ms 帧 + burst×2~4 ≈ 8ms |
| 编码 | Concentus 纯 JVM，~1ms | 同 | libopus，6.5ms lookahead |
| 网络 | LAN 1-3ms + 房主转发 1-2ms | 同 | 同 |
| 抖动缓冲 | **固定 3 帧 = 60ms**，max 10 帧 | `prebufferFrames=2`(40ms)，自适应 20~60ms | 自适应 20~40ms |
| 播放 | AudioTrack buffer 80ms | 降到 `*2`=40ms | AAudio LowLatency+Exclusive ≈ 8ms |
| **合计（估算）** | **约 124-167ms** | **约 84-107ms** | **约 55-75ms** |

**结论：120ms 用 P0 调参即可达标，Oboe 不是首版必需**，但路线 A 要求它，故放 P1 作为"提音质到 48kHz + 留余量"的升级。不要为了上 Oboe 拖住首版可跑通。

### 6.2 `JitterBuffer.kt` 自适应改造

保留 `PollResult` 三态（NotReady / Lost / Packet）与 16 位序号 `unwrap()`，把两个常量改成动态 target：

```kotlin
class JitterBuffer(
    private var targetMs: Int = 40,          // 20..60
    private val frameMs: Int = 20,
) {
    private var smoothedJitterMs = 0.0
    fun onNetworkSample(jitterMs: Int, lossRate: Double) {
        smoothedJitterMs = 0.9 * smoothedJitterMs + 0.1 * jitterMs
        targetMs = (smoothedJitterMs * 2 + if (lossRate > 0.05) 20 else 10)
            .toInt().coerceIn(20, 60)
    }
    // prebufferFrames = ceil(targetMs / frameMs)，其余 put/poll/unwrap 逻辑不变
}
```

`poll()` 返回 `Lost` 时仍用 `OpusCodec.decode(null)` 触发 PLC；`NotReady` 时**不要**补 PLC（这是原实现特意修过的坑，`JitterBuffer.kt:21-23`）。

### 6.4 "不做锁屏"的边界

保留 `IntercomForegroundService.kt`（`foregroundServiceType="microphone"`，`AndroidManifest:98-101`）——它不是锁屏功能，是防止切后台后系统回收麦克风与 socket，**删了会导致通话一退到后台就断**。
明确不做：`setShowWhenLocked` / `FLAG_SHOW_WHEN_LOCKED`、Keyguard 覆盖、锁屏 PTT 键、耳机 MediaSession 锁屏拦截、`PARTIAL_WAKE_LOCK` 唤醒屏幕、浮窗。若你连后台保活也不想要，把 `IntercomForegroundService.start()` 调用注释掉即可（一行）。

       ->setSharingMode(oboe::SharingMode::Exclusive)

## 8. 分阶段实施与验收

### P0 — 跑通（copy 为主，目标：可通话 + 测出延时基线）

1. 新工程建 `LICENSE`(GPL-3.0-or-later) / `THIRD_PARTY_NOTICES` / `NOTICE.changes`；按 §4.1 复制文件并补文件头声明。
2. 按 §4.2 删除无关模块，按 §6.3 摘除加密耦合。
3. 按 §6.1 把 `prebufferFrames 3→2`、AudioRecord/AudioTrack buffer `*4→*2`。
4. 接上 UI 的最小 PTT 按钮与房间列表；保留 FGS。
5. 两台真机连同一手机热点，建房/加入/PTT 对讲。

**验收**：无外网出口（抓包确认）、双向 PTT 可听、无啸叫、切后台不断、`flutter test` 与 `JitterBufferTest`/`OpusCodecTest` 通过、`THIRD_PARTY_NOTICES` 齐全。

### P1 — 路线 A 落地 + 补齐能力

6. 接 Oboe + 官方 libopus（§6.5），升 48kHz/10ms，开 DTX/FEC/PLC。
7. `JitterBuffer` 改自适应 20~60ms（§6.2），加按丢包率自适应码率。
8. 加 floor control（同按互斥 + 超时释放），补齐房主接管/断线重连回归。
9. `session_metrics.dart` 增加分段延时打点。

**验收**：5-15% 丢包无可闻断裂；3 台以上房主转发正常；48kHz 链路主观音质优于 P0；运行时依赖树只含宽松许可 + 自有 GPL 代码。

### P2 — 120ms 达标与收尾

10. **mouth-to-ear 实测**：A 端发短脉冲，第三台设备同时录 A 发声与 B 外放，量波形起点差；≥100 次取 p50/p95/p99，**p95 < 120ms** 为硬指标。配合随包时间戳（Oboe `getTimestamp()`）拆出采集/帧/lookahead/网络/jitter/播放各段。
11. 热点拉距、AP 客户端隔离、多人并发、房主掉线选举。
12. 可选：App 内一键开热点（clean-room `startLocalOnlyHotspot`，**不参考 MotoIntercom 源码**）。
13. 发布：源码公开、APK 与对应源码同版本、`THIRD_PARTY_NOTICES` 随包。

## 9. 风险与回退

| 风险 | 影响 | 处置 |
|---|---|---|
| 挂成 GPL-2.0-only | Apache-2.0 代码不能合法合并 | **已定 GPL-3.0-or-later**，写进 LICENSE 与 README |
| 误 copy 无 LICENSE 仓库（尤其 MotoIntercom 的热点代码） | 版权侵权 | 该文件只能 clean-room；CI 加"来源白名单"检查 |
| 删加密时漏改 `sendFrame` / `bindMemberForSessionToken` | 帧发不出去或成员绑定失败 | `send_pipeline.dart` 已有单测；先跑 `flutter test` 再上真机 |
| P0 调参后 p95 仍 >120ms | 不达标 | 直接跳 P1 上 Oboe；或再把帧降到 10ms + jitter 1 帧 |
| 硬件 AEC 机型差异 | 部分设备啸叫 | `isAvailable()` 探测降级；PTT 本地静音兜底；必要时编 AEC3 |
| 房主转发多一跳 | +1~2ms 且房主成单点 | 已有 `host_failover.dart` 自动选举；≤6 人场景可接受 |
| Flutter 技术栈被接受后想改原生 | 会话/传输层需重写 | 已在 §0 说明；若确定改原生，先决策再动工 |
